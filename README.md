# RagProof

RagProof 是供一人在本机使用的**资料问答与质量检查工具**。上传自己的文档后，可以用日常语言提问，查看回答及其出处；需要维护这套问答能力时，可以用一组已核对的问题检查调整带来的变化。

这里的 RAG 指“先从资料中寻找相关内容，再依据找到的内容回答问题”。

## 谁会使用

- **查资料的人**：上传产品手册、制度或其他资料，提问并核对答案依据。例如问“这款设备支持离线使用吗？”，查看回答引用的手册、页码和段落。资料没有提供足够依据时，工作台会说明情况；问题缺少关键条件时，可以补充条件后继续。
- **维护资料问答的人**：更新资料、调整模型或检索设置后，检查常见问题的回答和引用是否仍然可靠。例如更换检索设置后，重新检查一组经过人工核对的保修问题，找出回答发生变化的题目。

## 两项核心能力

### 知识库问答

上传 PDF、Word、Excel 或 HTML，查看文档的处理进度和已发布版本；围绕这些资料连续提问，查看回答、引用片段和可公开的检索过程。对话和处理任务保留历史，刷新页面后仍可查看；等待补充条件的问题可以继续完成。

知识库问答可以独立使用。

### RAG 评测

使用者准备一组问题及人工核对的预期结果。评测批量调用知识库问答所用的检索与回答能力，保存每题实际答案、引用依据、错误和评分原因。两次运行具备可比条件时，可以逐题查看改善、退步与无法判断的结果，并检查预设的质量要求。

评测用于检查问答能力的变化。文档内容发生变化、预期答案随之改变时，需要重新核对题目及其预期结果；缺少可靠依据的评分会显示为不可计算。自动评分仍需人工复核。

## 核心技术亮点

- **复杂问题拆解**：把需要多处信息的问题拆成子问题，分别检索和判断证据，再合并成一份回答。例如比较两份制度的适用条件与例外情况。
- **多路检索与证据筛选**：结合语义和关键词寻找相关片段，利用文档层级补全上下文，并对候选证据排序；回答保留可核对的来源引用。
- **证据不足时有界纠错**：尝试调整检索问题并重新判断证据；缺少可靠依据时明确说明，外部服务故障单独呈现。
- **人工介入（HITL）**：问题缺少关键条件时请求补充，存在多个范围时请使用者选择；收到输入后继续原来的回答任务，刷新页面也能找回等待状态。
- **持久模型配置与职责分工**：分别保存 Answer（生成回答）、Fast（规划与改写）、Grader（判断证据）、Evaluator（评测打分）四种模型职责的配置。任务记住所用模型，后续配置变动不会影响已有任务。
- **文档版本与可恢复运行**：新文档版本完成处理后发布，处理失败保留已发布内容；问答过程、引用和任务状态可以在页面刷新或服务重启后回看。
- **共用的真实问答链路**：日常提问与题集评测使用同一套检索、证据判断和回答能力，评测结果保留每题的运行条件与证据身份。

## 可信与使用边界

- 回答关联具体文档版本和证据片段；运行记录保留所用模型与检索设置的身份，便于核对结果来源。
- 资料缺少答案、证据不足、外部模型服务故障与任务取消分别显示相应状态。关闭页面仅停止查看进度，任务状态以服务端记录为准。
- 文档内容作为不可信输入处理；模型服务密钥保留在服务端，公开结果只展示必要的安全摘录，不展示模型私有推理。
- 本产品面向本机单人使用。开放到局域网或公网需要额外设计身份认证、授权和部署安全措施。
